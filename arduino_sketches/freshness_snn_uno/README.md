# Banana Freshness SNN for Arduino Uno

This sketch reports `FRESH`, `SPOILED`, or `NO_FRUIT` using MQ3 on `A3`, MQ5 on `A5`, and MQ135 on `A0`. It averages 20 ADC readings per prediction, applies the raw MQ3 `NO_FRUIT` gate, then maps banana readings with `open = custom × gain + offset` from `freshness_snn_model.h`.

For banana readings, the sketch computes the same nine engineered features as [freshness_snn_model.py](../../freshness_snn_model.py): MQ3/MQ135, MQ3/MQ5, MQ3−MQ5, MQ3−MQ135, MQ5/MQ135, sample sensor standard deviation, MQ5−MQ135, MQ5+MQ135, and MQ3. Each feature feeds its own fixed rate-coded leaky integrate-and-fire neuron for eight steps. The nine spike counts feed a trained quantized linear readout. The generated model occupies **94 bytes of flash data**, and every feature has a nonzero readout weight.

Regenerate the header with `.venv/bin/python export_arduino_snn.py`. The exporter trains only on open banana fresh and rotten recordings sorted by `Ticks` and summarized once per observed second within each burst. Its decision threshold is the 80th percentile of spoiled training scores, which reserves margin for recording drift without using the held-out rows during fold fitting. The first 20% of custom fresh and custom spoiled recordings fits the affine sensor mapping, and the remaining 80% validates it. The first 60% of no-fruit fits the raw MQ3 gate. The quantized SNN reached **0.9525 mean blocked balanced accuracy**, **0.8123 pooled leave-one-complete-session-out balanced accuracy**, and **1.0000 balanced accuracy on both the final-session chronological validation and held-out custom fresh/spoiled validation**. It also classified all 2,485 held-out no-fruit rows correctly.

The 1.54-inch monochrome GxEPD2 display uses `CS=D10`, `DC=D9`, `RST=D8`, and `BUSY=D7`. Serial output uses **115200 baud**. A local AVR build with the installed display libraries used **17,660 bytes of program memory** and **665 bytes of static RAM**, within the Uno's limits. The legacy open-data MQ5/MQ135 column swap and a physical hardware upload still need verification.
